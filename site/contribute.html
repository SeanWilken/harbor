Build it with us

harbor is a small codebase with a clear shape: F# on .NET 10 for the hub, agent and tray, a React UI built with bun, and PostgreSQL behind the hub. If you like typed functional code, git internals or calm interfaces, there's something here for you. The canonical guide is CONTRIBUTING.md; this page is the tour.

F# · .NET 10

Hub (ASP.NET minimal APIs), lean agent, Avalonia tray. Pure decision modules, I/O at the edges.

TypeScript · React

React 19 + Vite, built with bun. No UI framework; one stylesheet of theme tokens.

PostgreSQL 18

grate migrations, SqlHydra typed queries, an append-only event table.

Run it locally

dotnet build harbor.slnx
dotnet test                              # tests/Harbor.Tests, xUnit
cp harbor.example.json harbor.json       # gitignored
(cd ui && bun install && bun run build)
dotnet run --project src/Harbor          # hub + local agent on :7420
(cd ui && bun run dev)                   # hot reload on :7421

No hub handy? harbor-agent snapshot and harbor-agent manifest print exactly what an agent would send.

How we write code

  • Match the file you're in. Local consistency beats anyone's global preferences.
  • Small, composable functions. Decisions are pure and tested; I/O is pushed to the edges.
  • Comments say why. Most functions need none.
  • Strict types by default, looser where it buys real composability (and say so).
  • Tests where they earn their place: parsers, decisions, anything security-relevant.
  • Light by default. New collection should be cheap, change-driven and redacted for viewers.

Good places to start

collectors

winget, Homebrew, npm -g, pipx, dotnet tools. Each is a parser plus a test.

ui

Phone-width polish, long hostnames, accessibility passes over tables and dialogs.

protocol

A JSON schema and golden fixtures for the agent protocol, so other agents can be written against it.

redaction

Credential-shaped data in error text and job output is still to do.

Roadmap items (peer hubs, context sync, essence profiles, issues/tasks sync, desktop view) are being designed now. Open an issue before building on them so the work lines up.

Pull requests

One change per PR, a short description of what and why, and how you checked it (dotnet test, bun run check, a screenshot for UI changes). Contributions are licensed under Apache-2.0.
